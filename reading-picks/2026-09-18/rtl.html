RTL · VERIFICATION

Why verification traceability must evolve for modern systems

요구사항과 RTL, 테스트, 설정, 결과를 따로 보관하지 말고 ‘무엇을 어떤 조건에서 검증했는가’를 연결된 evidence로 남기자는 기술 노트.

요구사항→설계 컨텍스트→테스트→설정→결과를 연결한다.
Siemens Verification Horizons · Jake Wiltgen · 2026.09.11 · 약 4~6분

핵심 내용

  • Requirement, model, parameter, test, configuration, result가 서로 다른 도구에 흩어져 verification status 재구성이 어렵다.
  • Traceability를 검증 종료 후 문서화가 아니라 lifecycle 안에서 생성되는 engineering data로 다뤄야 한다.
  • 설계 변경 시 영향 범위와 재검증 대상을 추적할 수 있어야 coverage가 근거가 된다.

기술적 함의

RTL 설계자 입장에서는 regression pass/fail보다 ‘이 테스트가 어느 requirement와 어느 RTL/configuration을 증명하는가’가 중요해진다는 뜻이다.

실무 연결

  • golden C++/SystemC/RTL 단계에서 같은 requirement ID 유지.
  • valid/busy, latency, 4-port access 같은 설계 계약을 test와 직접 연결.
  • RTL 변경 시 영향을 받는 test subset을 찾는 regression 전략.
