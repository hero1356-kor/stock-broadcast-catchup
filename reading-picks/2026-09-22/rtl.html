AI가 RTL을 쓰는 것보다 먼저 바뀌는 곳: spec → verification

실제 NVM IP 팀에서 datasheet 해석·오류 탐지·verification plan·UVM testbench 생성까지 하나의 agentic flow로 묶었다.

SemiIPHub / ChipAgents · 2026-09-21 · 예상 읽기 7~9분

핵심 3개

  • eMemory의 NeoFuse NVM IP 사례에서 datasheet 분석과 verification testbench 구성 작업이 약 4일에서 5시간으로 줄었다고 보고했다.
  • 10개 datasheet의 120개 표·그림·timing diagram을 구조화하고, 의도적으로 넣은 15개 오류를 모두 검출했다고 한다. 이후 verification plan과 UVM testbench를 생성했다.
  • 생성된 환경은 기존에 없던 시나리오를 추가해 test pattern을 18%, functional coverage를 5% 늘렸다고 보고한다. 수치는 vendor 사례이므로 독립 벤치마크처럼 받아들이면 안 된다.

왜 읽을 만한가

흥미로운 지점은 “LLM이 SystemVerilog를 잘 쓴다”가 아니다. spec → structured facts → rule check → verification plan → executable testbench라는 중간 표현을 명시한 것이다. 신뢰성이 필요한 설계 자동화에서 agent가 자유롭게 코드를 생성하는 것보다 훨씬 현실적인 구조다.

특히 걸리는 포인트

이미지 처리 IP에서도 요구사항·golden C++·SystemC/HLS·hand RTL 사이에 동일한 문제가 생긴다. 예를 들어 4-port coordinate, valid/busy, border condition, LUT access rule을 machine-readable constraint로 만들고 그 규칙에서 test scenario와 assertion을 파생시키면, AI를 “코드 작성자”보다 “spec-to-check 연결기”로 쓰는 셈이다. 이쪽이 당장 실무 적용 가능성이 더 높다.
