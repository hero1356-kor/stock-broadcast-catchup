Hardware–Software Co-Design In The AI Era

HW와 SW를 동시에 최적화해야 하지만, 서로 다른 언어·툴·개발 cadence와 늦은 virtual platform이 병목이 된다는 분석.

Semiconductor Engineering · Brian Bailey · 2026.09.15 · 약 10~12분
실제 workload를 충분히 일찍 HW 모델 위에서 돌려 feedback loop를 만드는 것이 핵심이다.

핵심 내용

  • HW와 SW 조직은 언어·툴·개발 속도가 달라 co-design이 구조적으로 어렵다.
  • 소프트웨어가 실제 하드웨어 이전에 실행될 virtual model이 필요하지만 정확도와 속도 사이 trade-off가 크다.
  • AI가 개발을 도와도 workload를 architecture decision으로 연결하는 문제까지 자동 해결하지는 않는다.

기술적 함의

핵심 abstraction은 단순 기능 모델이 아니라 software workload를 실행하면서 throughput, latency, memory traffic 같은 architecture metric을 관찰할 수 있어야 한다. 모델이 너무 늦게 나오면 co-design의 feedback advantage가 사라진다.

실무 연결

  • golden C++와 SystemC 사이 공통 성능 contract를 정의할 것
  • HLS pragma 전에 workload와 memory bottleneck을 먼저 모델링할 것
  • SystemC를 RTL 생성용 소스뿐 아니라 executable architecture model로 활용할 것
RTL 관점의 한 줄: 좋은 HLS flow는 C→RTL 변환보다 workload→architecture→측정→수정의 반복 시간을 줄인다.
