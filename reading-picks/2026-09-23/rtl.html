RTL · EDA · ENGINEERING NOTE

AI의 다음 역할: RTL 생성기가 아니라 EDA 오케스트레이터

그럴듯한 Verilog 한 번 생성하는 단계에서 벗어나, 툴 피드백과 설계 문맥을 유지하며 전체 flow를 조정해야 한다는 관점이다.

단발성 artifact 생성 → 툴 피드백 반복 → 여러 EDA stage를 연결하는 의사결정 계층.
Semiconductor Engineering / University of Edinburgh perspective 소개 · 2026-09-19 · 약 8~12분

핵심 내용

논문은 LLM의 역할을 Generator → Agent → Orchestrator의 세 계층으로 본다. 현재 접근의 함정은 문법적으로 그럴듯한 RTL을 만드는 데 최적화되면서 실제 합성·PPA·verification 결과와 분리되는 ‘syntax trap’이다.

기술적 함의

산업 설계에서는 한 번의 코드 생성보다 spec → RTL/HLS → lint/sim → synthesis → timing/PPA → 수정의 폐루프가 중요하다. 각 stage의 결과를 다음 의사결정에 전달하고 설계 문맥을 잃지 않는 구조가 핵심이라는 주장이다.

실무 연결

Python/hand RTL → golden C++ → SystemC HLS → Stratus 같은 흐름에 그대로 대응된다. AI에게 RTL 전체를 맡기는 것보다 먼저 golden 비교, regression 결과 요약, synthesis report 해석, 실패 원인 분류와 다음 수정 후보 생성을 한 loop로 묶는 편이 현실적인 자동화 경로다.
