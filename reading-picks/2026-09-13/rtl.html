RTL · MEMORY · SHIFT LEFT

How shift-left memory contention analysis protects performance and schedule

두 개의 driver나 power path가 같은 node를 동시에 잡는 contention을 layout 이후가 아니라 schematic 단계에서 찾아야 하는 이유를 보여주는 기술 글.

Siemens Calibre · Chun-Hsiang Chang · 2026.09.01 · 약 6분
핵심 이미지: 서로 다른 control path가 shared node를 동시에 활성화하는 충돌을 schematic 단계에서 탐지한다.

핵심만 3개

  • 현대 SoC의 SRAM, HBM, VRAM, LPDDR 계층이 복잡해질수록 decoder, power switch, shared bus에서 예상치 못한 동시 activation 가능성이 커진다.
  • 전통적인 vector simulation만으로는 잘 안 걸리는 rail contention이나 edge-case logic race를 connectivity/state-aware schematic analysis로 더 일찍 찾을 수 있다.
  • 이미 검증된 반복 memory macro는 black-box 처리하고 새로운 interface와 integration logic에 집중하면 분석 시간을 줄일 수 있다.

왜 읽을 만하냐면

RTL 설계자에게도 꽤 직접적으로 연결된다. 결국 contention은 물리 단계만의 문제가 아니라 enable decode, arbitration, power state, reset/clock crossing 같은 제어 논리가 만들어내는 경우가 많다. hand RTL에서 mutually exclusive 조건을 명확히 설계하고 assertion으로 박아두는 이유와 정확히 닿아 있다.

나한테 특히 걸리는 포인트

  • one-hot 또는 mutually exclusive enable을 architecture 단계에서 명시할 필요
  • shared resource arbitration을 기능 검증과 power intent 양쪽에서 보는 관점
  • simulation에서 안 터졌다는 사실과 구조적으로 안전하다는 사실은 다르다는 점
RTL 관점의 한 줄: contention은 파형에서 우연히 잡는 bug가 아니라, 가능한 activation path 자체를 구조적으로 증명해야 하는 문제다.
