RTL · VERIFICATION · SYSTEM CONFIDENCE

RTL closure에서 ‘실행 가능한 시스템 신뢰도’로

2026 Functional Verification Study가 보여주는 핵심 변화: 버그가 RTL 블록 안보다 RTL·firmware·workload·reset·integration의 경계에서 더 많이 생긴다.

Siemens EDA / Verification Academy · 2026-09-08 · 예상 읽기 10–15분

핵심 내용

604명의 IC/ASIC·FPGA 실무자 데이터를 묶은 연구는 verification이 더 이상 RTL functional closure만으로 끝나지 않는다고 본다. processor-rich architecture, firmware, clock/reset, safety/security, realistic workload가 결합되면서 실패 원인이 도메인 경계로 이동한다.

기술적 함의

블록별 coverage가 높아도 전체 시스템이 boot하고 실제 software sequence를 수행하며 reset/recovery corner를 통과한다는 보장은 없다. 따라서 verification plan도 interface assumption과 system scenario를 1급 객체로 다뤄야 한다.

실무 연결

지금 하는 IP 설계에 적용하면
golden C++ → SystemC/HLS → RTL에서 각 단계의 기능 일치만 보는 것보다, 4-port access pattern·valid/busy protocol·buffer contention 같은 실제 workload를 일찍 executable model에 넣는 편이 중요하다. 특히 hand RTL과 HLS RTL이 각각 맞더라도 주변 IP의 backpressure/reset assumption이 다르면 system-level failure가 남는다.

한 줄 결론

“RTL이 맞다”와 “시스템이 실제로 돈다” 사이의 간격이 verification의 새 주전장이다.
